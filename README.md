本仓库用于规划与实现一个区别于传统 2D 首页的个人博客网站：首页不是普通的 Banner 和文章流，而是一个可探索的 `3D 主机场景`。用户进入网站后，会先置身于一个带有 `Switch`、`PlayStation`、卡带、光盘、手柄、收藏物件的游戏空间中；点击核心物件后，镜头会进行一次具有电影感的运镜，并在合适的时机从 3D 场景自然切换到真正可阅读的 2D 内容页面。

当前仓库处于 `概念设计已完成、工程实现待启动` 的阶段。现阶段的重点不是直接堆代码，而是先把世界观、信息架构、首页镜头语言、交互映射和后续工程路径讲清楚，避免后续实现时只做成“酷炫但不好用”的 3D 页面。

> 当前定位不是“把整站都做成 3D 游戏”，而是“用 3D 场景做入口，用 2D 页面承接真正的内容阅读”。

<a id="project-overview"></a>
## 项目简介

`MEO_Blog` 想做的不是一个普通博客模板，而是一个带有强烈个人风格的数字展厅。

整个网站会分成两个层次：

1. `3D 入口层`
   负责第一眼印象、探索感、品牌感和导航体验。
2. `2D 内容层`
   负责文章阅读、项目浏览、归档检索和长期维护。

首页的核心概念，是一个 `主机游戏收藏陈列台`：

- 中央是一台放大的 `Switch`，作为主入口和主运镜目标
- 一侧布置 `PlayStation` 风格主机或底座，承载项目内容入口
- 周围点缀手柄、卡带、光盘盒、收藏摆件、奖杯、记忆卡等元素
- 每个物件都不只是装饰，而是和站内内容结构产生映射关系

这使得网站不再只是“看页面”，而是“进入一个属于作者自己的游戏空间”。

<a id="experience-goals"></a>
## 核心体验目标

这个项目希望同时满足以下三件事：

1. 第一眼足够特别
   用户打开首页时，就能感受到鲜明的主机游戏氛围，而不是通用模板感。
2. 交互路径足够顺
   用户点击对象后，摄像头运镜要自然，切换要有仪式感，但不能妨碍浏览。
3. 内容系统足够稳
   真正的文章页、项目页和归档页仍然回到清晰、可读、可维护的 2D 结构。

对应的体验顺序是：

`进入场景 -> 观察物件 -> 悬停反馈 -> 点击入口 -> 镜头运镜 -> 屏幕接管 -> 进入 2D 内容`

<a id="scene-concept"></a>
## 场景设定

参考图提供了一个很有价值的方向：通过桌面静物、居中主物件、干净留白和实体摆件，建立一个“有故事的桌面空间”。本项目会保留这种 `陈列式构图` 的优点，但把主题从复古办公桌改为 `主机游戏房间 / 收藏桌台`。

推荐场景基调如下：

- 核心主题：`Switch + PlayStation + 收藏物件`
- 空间气质：私人房间、收藏桌面、夜间氛围灯、带一点展览感
- 材质语言：磨砂塑料、玻璃屏幕、拉丝金属、透明亚克力支架、橡胶按键
- 配色方向：炭黑、石墨灰、米白外壳，辅以 `Switch 红橙`、`PlayStation 蓝`、`荧光青绿`

建议的场景角色分配：

| 场景物件 | 对应内容 |
| --- | --- |
| 巨型 Switch 屏幕 | 博客首页 / 文章入口 |
| 左右 Joy-Con | 标签、分类、归档入口 |
| PlayStation 主机区域 | 项目作品 / 技术栈展示 |
| 卡带架 | 精选文章 / 系列内容 |
| 光盘盒 | 长文专题 / 作品集 |
| 手柄 | Lab / 实验交互 |
| 奖杯或人物摆件 | About / 个人经历 |
| 记忆卡或存档图标 | Guestbook / 联系方式 |

<a id="information-architecture"></a>
## 信息架构

推荐把站点结构拆成以下几个主路由：

- `/`
  3D 首页与入口场景
- `/posts`
  文章列表
- `/posts/[slug]`
  文章详情
- `/projects`
  项目页
- `/about`
  关于页
- `/lab`
  实验室
- `/archive`
  归档页
- `/guestbook`
  留言与联系

这里最关键的设计原则是：

- 3D 场景只负责入口与过场
- 2D 页面负责真正的内容承载
- 两者通过一次精心设计的相机动画连接起来

<a id="storyboard"></a>
## 首页分镜

首页的标志性体验可以拆成七段：

1. `Arrival`
   镜头以一个居中广角进入场景，整体只有轻微呼吸感。
2. `Discovery`
   鼠标移动时，镜头有细小视差，关键物件出现可探索暗示。
3. `Hover`
   悬停到 Switch、PS 主机、手柄或卡带区域时，边缘发光并出现短标签。
4. `Click`
   点击某个入口后，场景锁定交互，过场时间线启动。
5. `Orbit`
   摄像头绕主物件完成半圈到接近一圈的旋转，建立“过门”感。
6. `Align`
   镜头停在屏幕正前方，屏幕画面逐渐变得清晰，边框充满视口。
7. `Handoff`
   镜头推进穿过屏幕，3D 预览与真正的 2D 页面完成无缝切换。

Switch 路线最适合作为网站主入口，因为它天然拥有“屏幕作为门户”的视觉逻辑。

<a id="feature-design"></a>
## 功能设计

### 1. 内容模块

- 文章系统：支持 MDX、代码高亮、封面、目录、系列和标签
- 项目系统：展示项目简介、技术栈、截图、链接和过程记录
- About 页面：用更具游戏系统感的方式展示个人经历、技能和时间线
- Archive 页面：按年份、标签和专题整理内容

### 2. 3D 交互模块

- 首页 3D 场景渲染
- 关键物件热点映射
- 悬停高亮与提示标签
- 摄像机路径动画
- 3D 到 2D 的过场控制

### 3. 风格增强模块

- 环境灯光与房间氛围
- 轻量音效和交互反馈
- 自定义主题状态或彩蛋
- 可选的 `Skip Intro` 机制

### 4. 阅读体验模块

- 宽度舒适的正文排版
- 统一的代码块样式
- 阅读进度条
- 上一篇 / 下一篇导航
- 与场景物件风格呼应的卡片组件

<a id="tech-direction"></a>
## 技术方向

当前最推荐的实现组合是：

- `Next.js`
- `React Three Fiber`
- `@react-three/drei`
- `GSAP`
- `camera-controls`
- `MDX`
- `Blender`

这套组合的优势在于：

- 能稳定地把 3D 首页和 2D 内容页分层处理
- 文章页依然保持较好的 SEO 和可读性
- 3D 场景可以拥有足够强的表现力和扩展空间
- 后续既可以继续增强镜头编排，也能控制工程复杂度

## 说明

这个仓库最重要的价值，不是先把页面“搭出来”，而是先把体验路径设计清楚：

- 为什么要用 3D
- 哪些物件承担导航含义
- 摄像机如何叙事
- 什么时候从 3D 退回到 2D
- 怎么在保持惊艳感的同时保证内容阅读质量

当前这套方案已经把项目的世界观、交互主线和工程落地方向固定下来。后续实现时，整个仓库会围绕一个核心目标展开：

`把个人博客做成一个可进入、可探索、可阅读的主机游戏空间。`
